# `ExpressionValidationOnAsmWork.java`

Mode-aware validation work for expression-on-ASM. Extends `AbstractTransformationWork`. Nested `@Builder(builderMethodName = "expressionValidationOnAsmWorkParameter") @Getter ExpressionValidationOnAsmWorkParameter` holds `transformationMode`, default `TransformationMode.fromSystemProperty()`; read from `TransformationContext`, else defaults.
`execute()` order: required `ExpressionModel` + `MeasureModel` + `AsmModel` pulled from context first — each missing one throws `IllegalArgumentException` with the original message. Then branch: `transformationMode.isZeta()` (ZETA/DUAL) → `new ExpressionValidationOnAsmZetaWork(ctx).execute()`; ETL → `EtlEngineRegistry.require(ExpressionValidationOnAsmEtlEngine.class, ExpressionValidationOnAsmEtlEngine.ARTIFACT_COORDINATES).validate(models..., log)`, missing add-on throws `EtlEngineMissingException` naming `hu.blackbelt.judo.tatami:judo-tatami-expression-asm-validation-etl`.
No Epsilon import; module pom has no Epsilon dependency. EVL body (`StringBuilderLogger` + `ExpressionValidatorOnAsm.validateExpressionOnAsm`) now lives in `judo-tatami-expression-asm-validation-etl` `ExpressionValidationOnAsmEtlEngineImpl`. Tests: `ExpressionValidationOnAsmWorkEtlMissingTest` (core), `ExpressionValidationOnAsmWorkTest` (in `judo-tatami-expression-asm-validation-etl`). See change: split-etl-artifacts.
