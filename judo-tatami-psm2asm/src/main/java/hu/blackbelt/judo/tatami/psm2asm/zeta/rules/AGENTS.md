# judo-tatami-psm2asm/src/main/java/hu/blackbelt/judo/tatami/psm2asm/zeta/rules

Zeta rule classes for PSM→ASM, one per ETL module in `src/main/epsilon/transformations/asm/modules/`. Each class carries `@TransformationContext(source = ..., target = ...)`, declares a public no-arg constructor for `TransformationRegistry`, and exposes `TransformGuard` / `TransformFunction<S,T>` factory methods. Rule names come from static `Psm2AsmRuleNames` constants; ASM tree mutation goes through `Psm2AsmHelper`. Registration order is fixed in `Psm2AsmZetaTransformation.createRegistry()`: Namespace → Type → Data → TransferObject → Derived → Static → Operation → BoundTransferOperationAnnotation → Actor.

| File | Purpose |
|---|---|
| `ActorRules.java` | Port of the actor half of `accesspoint.etl`/`actor.etl`. Emits `EClass` per actor via `createActorTypeClass` (`ActorType`) and `createMappedActorTypeClass` (`MappedActorType`), plus `EAnnotation`s `createActorTypeAnnotation`, `createRealmAnnotation`, `createDocumentationAnnotationForActorType`. Guards `hasDocumentation` (non-null, non-empty `NamedElement.getDocumentation()`) and `hasRealm` (non-null, non-empty `AbstractActorType.getRealm()`). Depends on `TransferObjectRules` having produced the transfer-object classes — registered last (phase 8) for that reason. |
| `BoundTransferOperationAnnotationRules.java` | Declares the `BoundTransferOperation` → `EOperation` transformation context and nothing else — the class body holds only the registry constructor, no guards, no rules. Header states why: `CreateBoundAnnotationForTransferOperation` in `OperationRules` already covers `BoundTransferOperation` because it extends `TransferObjectType`'s `TransferOperation`, so the ETL rule `CreateBoundOperationAnnotation` needs no Zeta twin here. Registering it (phase 7b) is currently a no-op placeholder; removing it changes nothing in the output but loses the documented intent. |
| `DataRules.java` | Port of `data.etl`. Emits `EClass` per `EntityType` (`createEntityClass`, carrying `abstract` and super types), `EAttribute` per `Attribute` (`createAttribute`), `EReference` per relation (`createAssociationEndRelation`, `createContainmentRelation`), sequence annotations (`createNamespaceSequence`, `createEntitySequence`), and unmapped-default-only markers (`addUnmappedDefaultOnlyAttributeAnnotation`, `addUnmappedDefaultOnlyReferenceAnnotation`). Guard `isPrimitiveAttribute` filters attributes whose type is a PSM `Primitive`. `createAssociationEndRelation` leaves `EOpposite` unset — `Psm2AsmZetaTransformation.postProcess` step 2 pairs partners afterwards, so rules must not read `getEOpposite()` during transform. |
| `DerivedRules.java` | Port of `derived.etl`. Emits `EAttribute` via `createDataPropertyForDerivedAttribute` and `EReference` via `createNavigationPropertyForDerivedReference`, plus the JQL expression annotations `addPrimitiveAccessorExpressionAnnotation` / `addReferenceAccessorExpressionAnnotation`, the constraint annotations `addStringPrimitiveAccessorConstraints`, `addNumericPrimitiveAccessorConstraints`, `addCustomPrimitiveAccessorConstraints`, and `createDocumentationAnnotationForDataProperty`. Guards `isPrimitiveDataProperty`, `hasDocumentation`, `hasGetterExpression`, `hasReferenceGetterExpression`, `isStringPrimitiveAccessor`, `isNumericPrimitiveAccessor`, `isCustomTypePrimitiveAccessor`. The three accessor-type guards must partition primitive accessors; overlap emits duplicate `constraints` annotations on one member. Static accessors are handled by `StaticRules`, not here. |
| `NamespaceRules.java` | Port of `namespace.etl`; produces the ASM package tree the other rule classes attach to, hence registry phase 1. Exports `@Abstract namespaceToPackage` (base `Namespace` → `EPackage`), `modelToPackage` (`@Extends` base; `Model` → root `EPackage`, applying context attributes `nsURI` / `nsPrefix`), `packageToPackage` (`@Extends` base; nested `Package` → `EPackage`), `modelToPackageVersion` (version `EAnnotation`), and guard `hasVersion`. `namespaceToPackage` is `@Abstract` — it never fires standalone; children call `ctx.executeParentRule(NAMESPACE_TO_PACKAGE, s)`. Root packages are attached to the ASM resource only in `postProcess`, not here. |
| `OperationRules.java` | Port of `operation.etl`: bound/bound-transfer/unbound `EOperation`s, input parameters, script-body, behaviour, stateful, initializer and custom-implementation annotations (1970 lines). → see `OperationRules.java.AGENTS.md` |
| `StaticRules.java` | Port of `static.etl`. Exports `createUnmappedTransferObjectForStaticData` (`StaticData` → `EClass`) and `createUnmappedTransferObjectForStaticNavigation` (`StaticNavigation` → `EClass`), both `@Greedy`, producing the synthetic unmapped transfer objects that hold a single static query member. These sources are deliberately excluded from `DerivedRules` — the two classes partition PSM accessors and must be changed together. |
| `TransferObjectRules.java` | Port of `transferObject.etl`: mapped/unmapped transfer-object classes, reference classes for entities, transfer attributes and relations, plus their binding, constraint, permission and metadata annotations (1431 lines). → see `TransferObjectRules.java.AGENTS.md` |
| `TypeRules.java` | Port of `type.etl`. Emits one `EDataType`/`EEnum` per PSM type: `createEnumeration`, `createStringType`, `createIntegerType`, `createDecimalType`, `createBooleanType`, `createBinaryType`, `createDateType`, `createTimestampType`, `createTimeType`, `createCustomType`, plus annotations `createMeasuredAnnotationOfIntegerType` and `createBinaryConstraintsAnnotation`. Guards `isIntegerGuard`, `isDecimalGuard`, `isCustomTypeGuard`. `isCustomTypeGuard` is the catch-all counterpart of the EOL `type.eol` else-branch — it must stay mutually exclusive with the integer/decimal guards or a numeric type gets both a numeric and a custom classifier. Registered at phase 2 so classifiers exist before `DataRules` references them. |
