# `Psm2AsmWork.java`

Workflow work driving PSM→ASM with engine selection. Extends `AbstractTransformationWork`; exports `Psm2AsmWorkParameter` (`createTrace=false`, `parallel=true`, `useCache=true`, `transformationMode` defaulting to `TransformationMode.fromSystemProperty()`) and one constructor `(TransformationContext)`; the script-root `URI` constructor was removed.
`execute()` requires `PsmModel` in `TransformationContext` (missing one throws `IllegalArgumentException`), creates an empty `AsmModel` via `buildAsmModel()` when absent, puts it back into the context *before* transforming, calls `EmfPackages.addEmfPackagesToResourceSet` (Epsilon-free, judo-tatami-core) on the ASM resource set, then branches on `workParam.transformationMode.isZeta()` to `Psm2AsmZetaTransformation` or to the ETL engine: `EtlEngineRegistry.require(Psm2AsmEtlEngine.class, Psm2AsmEtlEngine.ARTIFACT_COORDINATES).execute(...)`; without `judo-tatami-psm2asm-etl` on the classpath it throws `EtlEngineMissingException` naming the artifact.
Zeta path ignores `createTrace`, `parallel` and `useCache` — those parameters only affect the ETL path. Result `Psm2AsmTransformationTrace` is put into the context; default engine is whatever the system property resolves to, so engine choice is ambient unless a `Psm2AsmWorkParameter` is placed in the context.

See change: split-etl-artifacts: core no longer references Epsilon; ETL branch delegates to the `-etl` add-on.
