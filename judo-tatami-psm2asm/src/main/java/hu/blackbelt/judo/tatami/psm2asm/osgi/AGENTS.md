# judo-tatami-psm2asm/src/main/java/hu/blackbelt/judo/tatami/psm2asm/osgi

OSGi wiring for PSM→ASM: a tracker watching registered `PsmModel` services and a transformation service producing `AsmModel` + `TransformationTrace` registrations. Both class names carry the upstream misspelling `Serivce` — public component name, do not "fix" without a coordinated rename.

| File | Purpose |
|---|---|
| `Psm2AsmTransformationPsmModelTracker.java` | Tracks `PsmModel` OSGi services and publishes the derived `AsmModel`. `@Component(immediate = true, configurationPolicy = ConfigurationPolicy.REQUIRE)` extending `AbstractModelTracker<PsmModel>`; `@Reference Psm2AsmTransformationSerivce`. Exports `activate(ComponentContext)` (opens the tracker on the bundle context), `deactivate()` (closes tracker, unregisters every `AsmModel` registration), `install(PsmModel)`, `uninstall(PsmModel)`, `getModelClass()` → `PsmModel.class`. Keys both `models` and `registrations` by `psmModel.getName()`, so two PSM models sharing a name collide — the second is rejected with an error log, not an exception. `install` swallows transformation failures into `log.error` and registers nothing; callers get no signal. `registrations` is a `ConcurrentHashMap` but `models` is a plain `HashMap` — the two maps are not guarded consistently under concurrent OSGi callbacks. `AsmModel` is registered with `asmModel.toDictionary()` as service properties. |
| `Psm2AsmTransformationSerivce.java` | Runs the ETL PSM→ASM transformation inside OSGi and publishes its trace. `@Component(immediate = true, service = Psm2AsmTransformationSerivce.class)`; exports `activate(BundleContext)`, `install(PsmModel)` → `AsmModel`, `uninstall(PsmModel)`. `install` builds an empty `AsmModel` at URI `asm:<psmModelName>.asm`, resolves the script root from the bundle entry `/tatami/psm2asm/transformations/asm/psmToAsm.etl` (that entry must be packaged in the bundle or `getEntry` returns null and `install` throws NPE), then calls `Psm2Asm.executePsm2AsmTransformation`. Resulting `Psm2AsmTransformationTrace` is registered as a `TransformationTrace` service with empty properties, so consumers cannot filter by model name. `createTrace` is left at its default `false`, so the registered trace carries no ETL trace map. Buffered ETL log is emitted yellow on success, red on failure, and the exception is rethrown. `psm2AsmTransformationTraceRegistration` is keyed by `PsmModel` identity in a plain `HashMap`; `uninstall` on an unknown model only logs an error. |
