# AGENTS.md — asm2rdbms

ASM→RDBMS transformation entry points: ETL driver, Excel mapping loader, workflow work unit, dual-engine trace, SQL-name abbreviator.

| File | Purpose |
|---|---|
| `AbbreviateUtils.java` | Shrinks a SQL identifier to a dialect length budget while keeping it readable and collision-resistant. Exports `abbreviate(String text, Integer maxLength, String separator)`. Splits camel-case and `_` into words, lower-cases, joins with `separator`, then deletes characters by English letter frequency — vowels `e a o i u` first, then consonants `t n s r h d l c m f y w g p b v k x q j z`, always from the rightmost word backwards and never the first character of a word. Throws `IllegalArgumentException` when `maxLength < 1`. Output is deterministic for a given input, and every generated table/column name depends on it — changing the frequency tables renames existing schemas. Injected into the Epsilon context under key `AbbreviateUtils`. |
| `Asm2Rdbms.java` | Drives the ETL engine over `asmToRdbms.etl`. Exports `executeAsm2RdbmsTransformation(Asm2RdbmsParameter)` (and a builder overload), `calculateAsm2RdbmsTransformationScriptURI()`, `calculateAsm2RdbmsModelURI()`, builder `asm2RdbmsParameter()`, constants `SCRIPT_ROOT_TATAMI_ASM_2_RDBMS`, `MODEL_ROOT_TATAMI_ASM_2_RDBMS`, `ASM_2_RDBMS_URI_POSTFIX = "asm2rdbms"`, nested `MD5Utils` with `md5(String)`. Loads the pre-built `mapping-<dialect>-rdbms.model` and merges its contents into the target `RdbmsModel` BEFORE running the ETL, so type/rule/name mappings are present. Derives length budgets from dialect — 16/60/62/58 by default, 6/28/30/30 for `oracle` — and only a positive explicit parameter overrides them. Injects `AbbreviateUtils`, `MD5Utils`, `asmUtils`, `rdbmsUtils`, the four `*Size` values, `createSimpleName` and the five prefixes (`T_`, `C_`, `FK_`, `FK_INV_`, `J_`) into the Epsilon context under exactly those names; the EOL operation library reads those keys. `asmModel`, `rdbmsModel`, `dialect` are `@NonNull`. |
| `Asm2RdbmsTransformationTrace.java` | Implements `TransformationTrace` over the ASM→RDBMS pair, carrying either the ETL trace (`Map<EObject, List<EObject>>`) or a Zeta trace — read through `isZetaTrace()`/`getZetaTrace()`/`getTransformationTrace()`, not the fields. Exports `fromModelsAndTrace(...)`, `resolveAsm2RdbmsTrace(...)`, `createAsm2RdbmsTraceResource(...)`, `getAsm2RdbmsTrace(...)`, `save(...)`, `getSourceModelTypes()` = `[AsmModel]`, `getTargetModelType()` = `RdbmsModel`. Trace URIs use postfix `asm2rdbms`. Round-tripping requires both source and target models registered in the resolving `ResourceSet`, else trace entries resolve to null. |
| `Asm2RdbmsWork.java` | `AbstractTransformationWork` unit, one instance per SQL dialect. Context keys are dialect-qualified: `putModel`/`getRdbmsModel` use `"rdbms:" + dialect`, `putAsm2RdbmsTrace`/`getAsm2RdbmsTrace` use `"asm2rdbmstrace:" + dialect` — two dialects can coexist in one `TransformationContext`. `execute()` requires an `AsmModel` in the context (throws `IllegalArgumentException` otherwise), registers the NameMapping/DataTypes/TableMappingRules metamodels on the RDBMS resource set, then dispatches on `Asm2RdbmsWorkParameter.transformationMode`. Zeta path loads `mapping-<dialect>-rdbms.model` itself, runs `Asm2RdbmsZetaTransformation`, and flattens the Zeta trace entries into the legacy `Map<EObject, List<EObject>>` so the result stays XMI-serialisable. `Asm2RdbmsWorkParameter` defaults `transformationMode` to `TransformationMode.fromSystemProperty()` and mirrors the naming knobs — note its field is `columnMaxNameSize` while `Asm2RdbmsParameter` calls it `columnNameMaxSize`. |
| `ExcelMappingModels2Rdbms.java` | Builds the `mapping-<dialect>-rdbms.model` that `Asm2Rdbms` later consumes, by running the three Excel loader ETLs. Exports `injectExcelMappings(RdbmsModel, Logger, URI scriptUri, URI excelModelUri, String dialect)`, `calculateExcelMapping2RdbmsTransformationScriptURI()`, `calculateExcelMappingModelURI()`, `calculateURI(String)`, `main(String[])`. Registers Epsilon model contexts `RDBMS`, `TYPEMAPPING` (`RDBMS_Data_Types_<Dialect>.xlsx` + `typemapping.xml`), `RULEMAPPING` (`RDBMS_Table_Mapping_Rules.xlsx` + `rulemapping.xml`), `NAMEMAPPING` (`RDBMS_Sql_Name_Mapping.xlsx` + `namemapping.xml`) — the ETL scripts address those exact names. Executes `excelToNameMapping.etl`, `excelToTypeMapping.etl`, `excelToRules.etl` in that order, then commits. `main(rdbmsModelFile, dialect)` is the build-time generator; it registers the three mapping metamodels first, else the model will not serialise. `calculateURI` handles plain directory, `.jar` and `jar:bundle:` code sources — do not simplify it, OSGi depends on the bundle branch. The type-mapping workbook name capitalises only the first letter of the dialect. |
