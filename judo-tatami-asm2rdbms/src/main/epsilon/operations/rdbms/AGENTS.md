# AGENTS.md — asm2rdbms/epsilon/operations/rdbms

EOL operations on the RDBMS target side: type mapping onto `RdbmsField`, rule tracing.

| File | Purpose |
|---|---|
| `_importRdbms.eol` | Include point for the RDBMS-side operation library — imports `field.eol`, `rule.eol`, `table.eol`. Pulled in by `operations/_importAll.eol`; a new RDBMS operation file must be listed here to reach the ETL rules. |
| `field.eol` | Fills an `RDBMS!RdbmsField` from a `RDBMS!TypeMapping` looked up by `asmType`. Exports `RdbmsField.fillType(type : String)`, `RdbmsField.fillType(type : String, attribute : ASM!EAttribute)`, `RdbmsField.fromType(type : RDBMS!RdbmsField)`, `String.parseAnnotationName()`, `String.parseAnnotationDetailsKey()`. Both `fillType` overloads throw `"Cannot resolve typemapping: <type>"` when no mapping matches, so the RDBMS model must carry a `TypeMapping` for every ASM type in use. A `rdbmsSize`/`rdbmsPrecision`/`rdbmsScale` value starting with `#` is an indirection of form `#<annotation>:<key>` resolved off the attribute's extension annotation — the two-arg overload reads the real value, the one-arg overload cannot and falls back to size 255 for `java.lang.String` only, leaving other `#`-typed fields unsized. `storageByte` is always forced to `-1`. `parseAnnotation*` assume the `#a:b` shape and index out of range otherwise. |
| `rule.eol` | Gives `RDBMS!Rule` a `toString()` dumping the full relation-shape decision record: `symbol`, `lower`/`upper`, `opposite`, `oppositeLower`/`oppositeUpper`, `containment`, `container`, `first`, `foreignKey`, `inverseForeignKey`, `readOnly`, `cascade`, `mandatory`, `rangeConstraint`, `inverseRangeConstraint`, `joinTable`. Diagnostic only — `reference.eol`'s `ruleMapping()` logs through it, so dropping a field here silently shrinks the transformation log. |
| `table.eol` | Inert: whole body is a commented-out `RDBMS!RdbmsTable.addSuperPrimaryKey(class : ASM!EClass)` that would have cloned the supertype's `EAttributeToTableIdField` equivalent into the table and set it as `primaryKey`. Defines no live operation; supertype primary-key propagation now happens in the ETL rules instead. Kept as the import target of `_importRdbms.eol`. |
