# AGENTS.md — asm2rdbms/epsilon/transformations/modules

ETL rule modules of `asmToRdbms.etl`, one per ASM source metaclass.

| File | Purpose |
|---|---|
| `attribute.etl` | Maps `ASM!EAttribute` onto RDBMS columns. `@abstract rule EAttributeToRdbmsField` fills type and name — enums and untyped attributes both degrade to `java.lang.Integer`, other types go through `fillType(s.eType.instanceClassName, s)`, `sqlName` from `fieldSqlName()`, `mandatory` hard-wired false (source `required` is commented out). `EAttributeToTableValueField` extends it, produces `RDBMS!RdbmsValueField` and appends to the containing class's `EClassToRdbmsTable` equivalent. `EAttributeToIndex` produces an `RDBMS!RdbmsIndex` named `IDX_<md5(uuid)>` for attributes `asmUtils.isIdentifier(...)` reports, referencing the attribute's `EAttributeToTableValueField` equivalent. All guards require `eContainingClass.isEntityType()` and skip derived attributes. IDs/`uuid` follow `(asm/<sourceId>)/<Suffix>` — trace resolution keys off them. Commented-out `EAttributeToUniqueKey` shows unique constraints were replaced by indexes. |
| `class.etl` | Maps `ASM!EClass` onto `RDBMS!RdbmsTable` plus nine mandatory system columns. `EClassToRdbmsTable` registers the table on the root package's `rootPackegeToModel` equivalent, sets `sqlName` from `tableSqlName()`, `name` from the classifier FQName, and links `parents` to the `EClassToRdbmsTable` equivalents of entity supertypes. Sibling rules add fixed columns: `ID` (`RdbmsIdentifierField`, `java.util.UUID`, also set as `table.primaryKey`), `TYPE` (mandatory String), `VERSION` (Integer), `CREATE_USERNAME`, `CREATE_USER_ID`, `CREATE_TIMESTAMP`, `UPDATE_USERNAME`, `UPDATE_USER_ID`, `UPDATE_TIMESTAMP`. Every rule guards on `s.isEntityType()`, so a non-entity class produces no table. The system-column SQL names are reserved — `attribute.eol` maps user attributes named `id`/`type`/`version` to `DOMAIN_*` to avoid the clash. |
| `package.etl` | Maps the ROOT `ASM!EPackage` (guard `eSuperPackage.isUndefined()`) onto the two RDBMS roots: `rootPackegeToModel` creates `RDBMS!RdbmsModel` with `name` from the package and `version` from program parameter `modelVersion`; `rootPackegeToConfiguration` creates `RDBMS!RdbmsConfiguration` with `dialect` from program parameter `dialect` and attaches it as `model.configuration`. `class.etl` resolves tables through `s.root().equivalent("rootPackegeToModel")`, so exactly one root package must exist. Rule names misspell "Package". |
| `reference.etl` | Maps `ASM!EReference` onto foreign keys and junction tables, dispatching on the spreadsheet-driven `s.ruleMapping()` `RDBMS!Rule` flags. `EReferenceToRdbmsTableForeignKey` (flag `foreignKey`) adds an `RdbmsForeignKey` to the SOURCE class's table pointing at the target table's primary key, names it `referenceIdentifierSqlName()`/`referenceFkSqlName()`, and sets `readOnly` + `deleteOnCascade` when the reference is a `container`. `EReferenceToRdbmsTableInverseForeignKey` (flag `inverseForeignKey`) adds the FK to the TARGET class's table instead, named `referenceInverseIdentifierSqlName()`/`referenceInvFkSqlName()`. `@lazy EReferenceToRdbmsJunctionTable` materialises the many-to-many table only when another rule resolves it, with `EReferenceToRdbmsJunctionTablePrimaryKey` (flags `joinTable` and `first`) creating its key and the bidirectional/unidirectional FK rules split on `s.eOpposite` presence. `first` makes a bidirectional pair produce ONE junction table, not two. All guards require both ends `isEntityType()` and skip derived references; `mandatory` is forced false everywhere (`isMandatory()` is commented out). |
