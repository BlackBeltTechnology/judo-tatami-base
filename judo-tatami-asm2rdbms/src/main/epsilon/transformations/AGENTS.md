# AGENTS.md — asm2rdbms/epsilon/transformations

ETL entry points: the ASM→RDBMS lowering plus the three Excel-sourced configuration loaders it depends on.

| File | Purpose |
|---|---|
| `asmToRdbms.etl` | Root ETL of the ASM→RDBMS lowering. Imports `../operations/_importAll.eol` then `modules/class.etl`, `modules/attribute.etl`, `modules/reference.etl`, `modules/package.etl` — all rules live in the modules. Its own `post` block rewrites `sqlName` on every `RDBMS!RdbmsElement` whose `uuid` matches a `RDBMS!NameMapping.fullyQualifiedName`, so `excelToNameMapping.etl` must have populated `NameMappings` into the same RDBMS model first; without it names stay as generated. Commented-out block would have added inheritance-based `RdbmsForeignKey` per parent table — superseded by the module rules. |
| `excelToNameMapping.etl` | Loads the SQL-name override sheet: rule `Excel2NameMapping` transforms `NAMEMAPPING!NameMapping` to `RDBMS!NameMapping`, copying `FullyQualifiedName`→`fullyQualifiedName` and `SqlName`→`rdbmsName`, appending to a fresh `RDBMS!NameMappings` root built in `pre`. Rows without `FullyQualifiedName` are skipped by the guard. Output is consumed by `asmToRdbms.etl`'s `post` block, matched on element `uuid`, so an FQ name that no element carries is silently ignored. |
| `excelToRules.etl` | Loads the relation-shape decision table: rule `Excel2Rule` transforms `RULEMAPPING!TableMappingRule` to `RDBMS!Rule` into a fresh `RDBMS!Rules` root. Copies `symbol`, `opposite`, `lower`/`upper`, `container`, `containment`, `first`, `foreignKey`, `inverseForeignKey`, `rangeConstraint`, `inverseRangeConstraint`, `joinTable`; defaults missing `readOnly`/`cascade`/`mandatory` to false, and sets `oppositeLower`/`oppositeUpper` to sentinel `-2` when `opposite` is false. Rows without `symbol` are skipped. `reference.eol`'s `ruleMapping()` resolves against `RDBMS!Rules.all.first`, so exactly one `Rules` root must exist. Bug: `cascade` is read from `t.cascade` (target) not `s.cascade`, so the spreadsheet's cascade column never reaches the model. |
| `excelToTypeMapping.etl` | Loads the ASM-type→SQL-type table: rule `Excel2TypeMapping` transforms `TYPEMAPPING!Mapping` to `RDBMS!TypeMapping` into a fresh `RDBMS!TypeMappings` root. Maps `Judo`→`asmType`, `Type`→`rdbmsType`, `JdbcType`→`rdbmsJdbcType`, parses `SqlType` as integer, and substitutes the string `"-1"` for blank `Size`/`Precision`/`Scale`. Rows without `Judo` are skipped. `field.eol`'s `fillType` looks mappings up by `asmType` and throws when absent, and treats a `#annotation:key` size/precision/scale value as an indirection — that convention must be preserved by the spreadsheet. |
