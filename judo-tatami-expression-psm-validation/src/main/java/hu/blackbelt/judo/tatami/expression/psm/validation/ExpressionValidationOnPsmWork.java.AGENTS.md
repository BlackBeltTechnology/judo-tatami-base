# `ExpressionValidationOnPsmWork.java`

Mode-aware validation work for expression-on-PSM. Extends `AbstractTransformationWork`. Nested `@Builder(builderMethodName = "expressionValidationOnPsmWorkParameter") @Getter ExpressionValidationOnPsmWorkParameter` holds `transformationMode`, default `TransformationMode.fromSystemProperty()`; read from `TransformationContext`, else defaults.
`execute()` order: required `ExpressionModel` + `PsmModel` pulled from context first — each missing one throws `IllegalArgumentException` with the original message. Then branch: `transformationMode.isZeta()` (ZETA/DUAL) → `new ExpressionValidationOnPsmZetaWork(ctx).execute()`; ETL → `EtlEngineRegistry.require(ExpressionValidationOnPsmEtlEngine.class, ExpressionValidationOnPsmEtlEngine.ARTIFACT_COORDINATES).validate(models..., log)`, missing add-on throws `EtlEngineMissingException` naming `hu.blackbelt.judo.tatami:judo-tatami-expression-psm-validation-etl`.
No Epsilon import; module pom has no Epsilon dependency. EVL body (`StringBuilderLogger` + `ExpressionValidatorOnPsm.validateExpressionOnPsm`) now lives in `judo-tatami-expression-psm-validation-etl` `ExpressionValidationOnPsmEtlEngineImpl`. Tests: `ExpressionValidationOnPsmWorkEtlMissingTest` (core), `ExpressionValidationOnPsmWorkTest` (in `judo-tatami-expression-psm-validation-etl`). See change: split-etl-artifacts.
